# Generated OpenAPI client adoption

Issue #39 migrates `PaletteAPIClient` from a hand-rolled `URLSession` client
to a typed client generated by
[swift-openapi-generator](https://github.com/apple/swift-openapi-generator)
from the OpenAPI document published by viamin/color_matching#110.

## What must land

- `ColorComposerCore/Package.swift` declares `swift-openapi-generator` (with
  the `OpenAPIGenerator` build plugin applied to the `ColorComposerCore`
  target) and links `swift-openapi-runtime`.
- The OpenAPI document is committed under `Sources/ColorComposerCore` —
  canonical location per the swift-openapi-generator scaffold:
  `Sources/ColorComposerCore/OpenAPI/openapi.yaml` (the guard test accepts
  `openapi.yaml`, `openapi.yml`, or `openapi.json` anywhere under the target
  sources).
- `PaletteAPIClient` either migrates onto the generated `Client` directly or
  (preferred) **wraps** it, keeping its public initializer
  `init(baseURL:token:session:)` and the `PaletteAPIError` surface.

Structural acceptance is pinned by
`ColorComposerCore/Tests/ColorComposerCoreTests/GeneratedOpenAPIClientTests.swift`.

## Migration notes (wrap, don't rewrite)

- **Transport injection:** construct the generated `Client` over a
  `URLSession`-backed transport built from the injected `session`, so the
  `MockURLProtocol`-based tests keep working unchanged.
- **Error mapping:** preserve the mapping `PaletteAPIClientTests` pins —
  HTTP 401 → `.unauthorized` (drives re-auth, issue #16), other non-2xx →
  `.badStatus(code)`, undecodable 2xx body → `.malformedResponse`,
  invalid base URL → `.invalidURL`.
- **Auth:** keep trimming the bearer token and sending
  `Authorization: Bearer <token>` only when non-empty.
- **Disk cache is untouched:** `ProfileColorCache` stores `PaletteColorDTO`
  wire DTOs and decodes hand-written snake_case files (see
  `testDecodesHandWrittenSnakeCaseCacheFile`). Keep DTO→domain conversion at
  the `PaletteAPIClient` boundary — either keep the DTOs or convert generated
  types into them — so per-server/profile color caching, offline-stale
  badges, and cached profile fallback behavior stay bit-identical.

## `/api/v1` wire shape as consumed today

The PR description must record any drift between this shape and the #110 spec.

- `GET /api/v1/printer_profiles` →
  `{"printer_profiles": [{"id": Int, "printer_make_model": String?, "paper_type": String?, "ink_type": String?}]}`
- `GET /api/v1/colors?printer_profile_id=N` →
  `{"printer_profile": <profile or null>, "colors": [{"id": Int, "name": String?, "hex": String, "rgb": {"r": Int, "g": Int, "b": Int}?, "palette_id": Int?, "palette_name": String?, "sort_order": Int?, "responses": {"<light_source>": {"brightness": Double, "source": String?, "raw_value": Double?, "raw_unit": String?, "apparent_brightness": Int?, "measured_at": String?, "test_run_id": String?}}}]}`
- Light sources are `white`/`red`/`green`/`blue`/`lps`; unknown keys are
  dropped on domain conversion (never treated as zero brightness).
- Optional bearer token; `testConnection` succeeds on any 2xx from
  `/api/v1/printer_profiles`.

Behavioral acceptance is pinned by `PaletteAPIClientTests` (auth, query
parameter, error mapping, `testConnection`) and `APIDecodingTests`
(envelopes, absent-vs-zero responses) — all must stay green through the
migration; `ProfileColorCacheTests` pins the cache/offline behavior.
