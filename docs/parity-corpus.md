# Solver parity corpus

`WeightedSquaredErrorScorer` deliberately mirrors the Elixir
`ColorMatching.WeightedSquaredError` + `IlluminantMatching.best_match/4`
reference in [`color_matching`](https://github.com/viamin/color_matching), so
client-side composition and server-side composition pick the same colors. The
parity corpus makes that mirror **enforced by tests** instead of by convention.

## Where the corpus lives

```
ColorComposerCore/Tests/ColorComposerCoreTests/Fixtures/ParityCorpus/parity_corpus.json
```

It is committed JSON, read directly from the source tree by
`SolverParityCorpusTests.swift` (no SwiftPM resource declaration needed, so it
also works under the portable Linux lint harness).

## What the tests assert

`SolverParityCorpusTests` runs every corpus case three ways:

1. **Corpus shape** — decodes, matches schema `color-matching.parity-corpus.v1`,
   unique case/candidate ids, only canonical light sources (`white`, `red`,
   `green`, `blue`, `lps`), and keeps at least one `tie` case and one
   `exclusion` case so a refresh cannot silently drop the case classes that
   historically drift.
2. **Scorer parity** — `WeightedSquaredErrorScorer` selection must equal
   `expected.selected_candidate_id` exactly (ties: earliest candidate in corpus
   order wins, mirroring `best_match/4`), each candidate's
   excluded-vs-ranked outcome must match `expected.excluded_candidate_ids`, and
   the winning score must match `expected.score` within 1e-12 when present.
3. **Solver fast path** — the same selection through the production
   `CompositionSolver` fast path on a 1×1 grid, including
   `excludedCandidateCount` and infinite error for all-excluded cases.

## Schema (v1)

```jsonc
{
  "schema": "color-matching.parity-corpus.v1",
  "cases": [
    {
      "id": "case-slug",                 // unique
      "tags": ["tie" | "exclusion" | "weights" | "doctest" | ...],
      "weights": { "white": 0.5, ... },  // omitted keys are weight 0
      "target": { "red": 0.5, ... },     // brightness per condition
      "candidates": [                    // order matters: ties resolve earliest
        { "id": 201, "name": "…", "hex": "#808000",
          "responses": { "white": 0.4, "red": 0.6 } }   // omitted = unmeasured
      ],
      "expected": {
        "selected_candidate_id": 201,    // null when every candidate is excluded
        "score": 0.02,                   // optional; checked within 1e-12
        "excluded_candidate_ids": []     // candidates that must rank .excluded
      }
    }
  ]
}
```

A missing `responses` key means *unmeasured* (never zero brightness): with
weight > 0 it excludes the candidate, with weight 0 it is ignored.

## Refreshing the corpus

The authoritative corpus is generated by the `color_matching` server (PR
[viamin/color_matching#111](https://github.com/viamin/color_matching/pull/111)),
which runs the Elixir reference solver over curated inputs:

```bash
git clone https://github.com/viamin/color_matching && cd color_matching
git checkout <branch of PR #111>
mix deps.get && mix test        # ensures the generator is healthy
mix parity.corpus > parity_corpus.json   # task name per PR #111; see its README
cp parity_corpus.json ../ColorMatching-macOS/ColorComposerCore/Tests/ColorComposerCoreTests/Fixtures/ParityCorpus/parity_corpus.json
cd ../ColorMatching-macOS/ColorComposerCore && swift test --filter SolverParityCorpusTests
```

If PR #111's generator emits additional fields, keep the schema string in sync:
bump `schema`, update the DTOs in `SolverParityCorpusTests.swift`, and record
the shape change in the PR description.

### Current content: hand-derived seed

Until PR #111 lands, the committed file is a **seed corpus** whose seven cases
are hand-derived from behavior documented in this repository and the Elixir
reference: the `WeightedSquaredError` doctest (expected 0.205), earliest-wins
ties, exclusion of candidates missing a required channel, zero-weight channels
being neither required nor contributing, weight-scaled winner flips, and an
all-excluded case. Replacing the seed with the generated corpus must keep the
`tie` and `exclusion` tags present (the shape test enforces this).
