# Solver parity corpus

`ColorComposerCore`'s `WeightedSquaredErrorScorer` deliberately mirrors the
Elixir `ColorMatching.WeightedSquaredError` solver and the earliest-wins
selection of `ColorMatching.IlluminantMatching`, so client and server agree on
selection. The **solver parity corpus** is the shared source of truth that
keeps the two implementations in lockstep: a deterministic golden-vector
fixture generated by the Elixir service and replayed by both test suites.

## Where the corpus lives

- **Upstream (source of truth):** [`priv/parity/v1/corpus.json`][upstream] in
  `viamin/color_matching` — produced by `mix parity.generate` (issue
  [#111][issue-111], landed as PR [#112][pr-112]). CI upstream verifies the
  committed bytes are byte-identical to a fresh build (`mix parity.generate
  --check`).
- **This repo (vendored test fixture):**
  `ColorComposerCore/Tests/ColorComposerCoreTests/Fixtures/parity/v1/corpus.json`
  — a byte-identical copy consumed by `swift test`.

## How the tests consume it

`SolverParityCorpusTests.swift` (in the `ColorComposerCoreTests` target):

1. Loads the fixture relative to `#filePath` — no `Bundle.module` resource
   declaration is required, so the suite runs under plain `swift test`.
2. Decodes the corpus envelope (`algorithm_version`, `scorer`, `selection`,
   `missing_policy`, `light_sources`) and asserts it still declares the
   semantics the replay assumes.
3. Replays every scenario through `WeightedSquaredErrorScorer`: scores every
   palette color against the target with the scenario's channel weights and
   compares the **full per-candidate score table** (`"excluded"` markers
   included), the selection, the selected error, and the tie evidence
   (`tie_broke`, `tied_indices`) — computed with the same earliest-wins rule
   as `CompositionSolver.bestCandidate`.
4. Replays the grid-expressible scenarios through `CompositionSolver`'s
   optimized fast path on a 1×1 composition, pinning that implementation to
   the corpus as well.

Score numbers are compared with `1e-12` tolerance (corpus values are exact
binary fractions, so summation order cannot matter); selections, tie sets, and
exclusion markers are compared exactly.

### Semantics pinned by the corpus

- **Ties:** exact score ties resolve to the **earliest palette index** —
  including a three-way tie where a later duplicate matches bit-for-bit.
- **Exclusions:** a candidate missing a measurement on any positive-weight
  channel is **excluded**, never treated as zero brightness; a target missing
  a positive-weight channel excludes every candidate (no selection). The
  all-excluded case is covered end-to-end (solver cell `nil`, error `∞`).
- **Weight handling:** zero-weight channels neither exclude nor contribute;
  weight keys outside the canonical set (`ultraviolet` in the corpus) are
  ignored; weights scale each channel's squared error.

## Refreshing the vendored copy

The corpus is deterministic upstream, so refreshing is a byte-for-byte copy:

```bash
cd ColorComposerCore/Tests/ColorComposerCoreTests/Fixtures/parity/v1
curl -fsSL -o corpus.json \
  https://raw.githubusercontent.com/viamin/color_matching/main/priv/parity/v1/corpus.json
shasum -a 256 corpus.json   # record in the table above, then commit
cd - && cd ColorComposerCore && swift test   # parity suite must stay green
```

If `algorithm_version` changes, every recorded expectation has moved: refresh
the fixture, re-run the parity suite, and revisit any scorer semantics this
app changed since. A red parity suite after a pure fixture refresh means real
client/server divergence — not a flaky test.

## Generated OpenAPI client migration (issue #39, implementation run)

The behavior the migration must preserve is pinned by two permanent suites —
run them before and after the migration; they must stay green unchanged:

- `PaletteAPIClientMigrationContractTests.swift` — `/api/v1` paths,
  `printer_profile_id` query, JSON `Accept` header, bearer-token handling
  (trimmed token, none when absent), envelope decoding, and the error mapping
  (`401 → unauthorized`, other non-2xx → `badStatus`, undecodable 2xx body →
  `malformedResponse`).
- `ProfileColorCacheTests.swift` — per-server/per-profile disk cache,
  offline-stale `fetchedAt` markers, cached-profile fallback (`allEntries`),
  and Clear Cache behavior; the cache stores wire DTOs, so it is agnostic to
  whether the DTOs came from the hand-rolled or generated client.
