# Solver parity corpus

`WeightedSquaredErrorScorer` (`ColorComposerCore/Sources/ColorComposerCore/CompositionScorer.swift`)
deliberately mirrors `ColorMatching.WeightedSquaredError` in the
[`color_matching`](https://github.com/viamin/color_matching) Elixir backend, so
the client and server select the same palette color for a given target. That
parity is enforced by `SolverParityCorpusTests`
(`ColorComposerCore/Tests/ColorComposerCoreTests/SolverParityCorpusTests.swift`),
which replays a corpus of scoring/selection scenarios generated by the server
and asserts this package's scorer and selection policy (lowest score wins,
earliest-candidate tie-breaking) reproduce every expected score, exclusion,
and tie exactly.

## Where the corpus lives

- **Upstream source of truth**: `priv/parity/v1/corpus.json` in
  `viamin/color_matching`, generated by `mix parity.generate`
  (see `viamin/color_matching#111`).
- **Committed copy in this repo**:
  `ColorComposerCore/Tests/ColorComposerCoreTests/Fixtures/solver_parity_corpus.json`
  — a verbatim copy of the upstream file, loaded at test time via `#filePath`
  (it is not declared as an SwiftPM resource, so no `Package.swift` resource
  wiring is required).

## Corpus shape

Top-level: `algorithm_version`, `scorer`, `selection`, `missing_policy`,
`light_sources`, and a `scenarios` array. Each scenario carries:

- `weights` — the per-channel weight map (may include light sources this
  package doesn't know about, e.g. `"ultraviolet"`, which must be ignored).
- `target` / `palette` — response vectors keyed by light source; a channel
  absent from a vector means "unmeasured," never "measured as zero."
- `expected.scores` — each candidate's score, or the literal string
  `"excluded"` when it (or the target) is missing a required channel.
- `expected.selected_index` / `selected_hex_color` / `error` — the winning
  candidate, or `null` for all three when every candidate is excluded.
- `expected.tied_indices` / `tie_broke` — every candidate sharing the lowest
  score, and whether more than one tied, so earliest-index tie-breaking is
  exercised deliberately rather than incidentally.

## Refreshing the corpus

1. In `viamin/color_matching`, run `mix parity.generate` (or pull the latest
   `priv/parity/v1/corpus.json` after a solver-affecting change lands there).
2. Copy that file verbatim over
   `ColorComposerCore/Tests/ColorComposerCoreTests/Fixtures/solver_parity_corpus.json`
   in this repo.
3. Run `cd ColorComposerCore && swift test --filter SolverParityCorpusTests`.
   A failure here means either this package's scorer has drifted from the
   server's `WeightedSquaredError`, or the corpus now covers a case this
   package doesn't yet handle — resolve the discrepancy before merging; do
   not edit the fixture to make a failure disappear.
