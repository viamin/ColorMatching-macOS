# Solver parity corpus

`WeightedSquaredErrorScorer` deliberately mirrors the Elixir
`ColorMatching.WeightedSquaredError` solver, and `CompositionSolver` mirrors
the `IlluminantMatching.best_match/4` selection policy. The parity corpus is
the executable proof: a data file of inputs with expected outputs computed by
an independent reference implementation, asserted case-for-case by
`ColorComposerCore/Tests/ColorComposerCoreTests/SolverParityCorpusTests.swift`
(issue #39).

## Where the corpus lives

- Committed fixture (used today):
  `ColorComposerCore/Tests/ColorComposerCoreTests/solver_parity_corpus.json`
- Upstream corpus (authoritative, once it lands): the solver parity corpus
  generated by the `color_matching` service (viamin/color_matching#111). The
  committed fixture is a hand-derived stand-in produced by
  `ColorComposerCore/Tests/ColorComposerCoreTests/generate_solver_parity_corpus.py`,
  which re-implements the Elixir semantics in Python and computes every
  expected outcome independently of the Swift code.

## What the harness asserts

- **Score cases** — one candidate, one target, one weight set: the scorer must
  return exactly the expected score (`1e-9` accuracy) or `.excluded`.
- **Selection cases** — a palette plus per-cell target vectors run through
  `CompositionSolver`: per-cell selected color id, per-cell error, and the
  excluded-candidate count must match exactly.
- **Tie cases** — equal winning scores must select the earliest palette entry
  (palette order, not color id). Tie cases use dyadic values (`0.0`, `0.25`,
  `0.5`, `0.75`, `1.0`) so the equality is exact in IEEE arithmetic rather
  than an ulp-level coincidence that could flip between the Elixir, Python,
  and Swift summations.
- **Exclusions** — a missing measurement on the candidate *or* the target for
  any positively-weighted condition excludes the candidate; measured-as-zero
  is *not* missing. When every candidate is excluded the cell stays unmatched
  with infinite error.
- **Weight handling** — zero-weight channels are ignored entirely (their
  absence never causes exclusion); weights multiply squared per-channel
  differences; re-weighting can flip a winner (the two `weight-flip` cases).

## Corpus schema (version 1)

```json
{
  "version": 1,
  "generator": "…",
  "cases": [
    {
      "id": "score-doctest-anchor",
      "kind": "score",
      "description": "…",
      "weights": {"white": 0.5, "red": 1.0, "green": 1.0, "blue": 0.0, "lps": 1.5},
      "candidate": {"white": 0.5, "red": 0.1, "green": 0.4, "blue": 0.0, "lps": 0.3},
      "target":   {"white": 0.8, "red": 0.2, "green": 0.7, "blue": 0.1, "lps": 0.5},
      "expected": {"outcome": "score", "value": 0.205}
    },
    {
      "id": "selection-tie-earliest-palette-order-not-lowest-id",
      "kind": "selection",
      "weights": {"white": 1.0},
      "palette": [{"id": 22, "hex": "#000000", "responses": {"white": 0.0}}, …],
      "cells": [{"white": 0.5}],
      "gridWidth": 1, "gridHeight": 1,
      "expected": {
        "selections": [22],
        "errors": [0.25],
        "ties": [true],
        "excludedCandidateCount": 0
      }
    }
  ]
}
```

Rules:

- Condition keys are the `LightingCondition` raw values (`white`, `red`,
  `green`, `blue`, `lps`); an **absent key means "missing measurement"**,
  a present `0.0` means "measured as zero". Non-positive weights are inactive.
- `cells` is row-major, length `gridWidth * gridHeight` (defaults: width =
  cell count, height = 1). Every cell must define every active condition.
- `expected.selections` / `expected.errors` use `null` for unmatched cells
  (infinite error). `ties[i]` is metadata recording that the winner shared
  its score with 2+ eligible candidates.
- Case ids keep the markers `doctest`, `zero-weight`, `excluded`, and `tie`;
  a coverage test fails the suite if a refresh drops them. The
  `score-doctest-anchor` case must keep reproducing the Elixir doctest
  expectation of `0.205`.

## Refreshing

- Regenerate the stand-in fixture after changing the case list:

  ```sh
  python3 ColorComposerCore/Tests/ColorComposerCoreTests/generate_solver_parity_corpus.py
  ```

- Consume the upstream corpus (viamin/color_matching#111) without touching
  the committed fixture by pointing the harness at it:

  ```sh
  SOLVER_PARITY_CORPUS_PATH=/path/to/color_matching/parity_corpus.json swift test
  ```

  Once the upstream corpus is vendored into this repository, replace the
  committed fixture with it (keeping the schema above, or extending the
  harness) and update this document.
