# Solver parity corpus & OpenAPI snapshot consumption

This app shares two machine-checked contracts with the
[`color_matching`](https://github.com/viamin/color_matching) server:

1. **Solver parity** — `WeightedSquaredErrorScorer` (and the `CompositionSolver`
   selection around it) must select exactly what the Elixir
   `ColorMatching.WeightedSquaredError` solver selects, including ties,
   exclusions, and weight handling.
2. **API shape parity** — `PaletteAPIClient` speaks `/api/v1`; the server now
   publishes an OpenAPI 3 spec for it (viamin/color_matching#110, merged as
   #113) and this repo generates its typed client from that spec (issue #39).

## Solver parity corpus

- **Upstream source:** `priv/parity/v1/corpus.json` in viamin/color_matching,
  generated by `mix parity.generate` (viamin/color_matching#111, merged as
  #112). Stamped `algorithm_version: 1`, `scorer:
  "ColorMatching.WeightedSquaredError"`, `selection: "earliest-index-wins"`,
  `missing_policy: "excluded-when-any-positive-weight-channel-missing"`.
- **Where it lives here (committed verbatim — do not hand-edit):**

  ```
  ColorComposerCore/Tests/ColorComposerCoreTests/Fixtures/parity/v1/corpus.json
  ```

- **How to refresh:**

  ```bash
  curl -o ColorComposerCore/Tests/ColorComposerCoreTests/Fixtures/parity/v1/corpus.json \
    https://raw.githubusercontent.com/viamin/color_matching/main/priv/parity/v1/corpus.json
  ```

  or copy the file out of a local `color_matching` checkout after running
  `mix parity.generate` there (regeneration is deterministic upstream). When
  upstream bumps `algorithm_version`, add a new `Fixtures/parity/vN/`
  directory instead of overwriting `v1` —
  `SolverParityCorpusTests.testCorpusMetadataMatchesSupportedParityContract`
  fails on an unsupported version so the bump is a deliberate, reviewed step.

- **What `swift test` asserts** (`SolverParityCorpusTests`): per-candidate
  scores, selected index/hex, winning error, tie sets and `tie_broke`
  evidence, earliest-wins tie-breaking, missing-measurement exclusions
  (candidate- and target-side), unknown weight keys ignored (the
  `ultraviolet` scenario), and agreement of the `CompositionSolver` fast path
  with the corpus selection for every replayable scenario. Corpus values are
  dyadic rationals, so score comparison is exact to within `1e-12`.

- **Parity findings at adoption (2026-11):** the Swift scorer already matches
  all 12 corpus scenarios — plain weighted squared-error sum (no per-channel
  mean), strict less-than comparison giving earliest-index wins, exclusion
  when any positive-weight channel is missing on either side, zero-weight
  channels ignored. No solver changes were needed or made (per the issue's
  non-goals).

## OpenAPI snapshot for the generated client

- **Upstream source:** the server serves the spec at `GET /api/v1/openapi.json`
  (unauthenticated — the route sits outside the `:api_auth` pipeline).
- **Where the snapshot lives (committed):** `ColorComposerCore/openapi.json`.
  `swift-openapi-generator` generates the typed client from it; the
  `PaletteAPIClient` surface (or its wrapper) keeps the disk-cache /
  offline-stale behavior intact.
- **How to refresh:**

  ```bash
  curl -o ColorComposerCore/openapi.json "$COLOR_MATCHING_URL/api/v1/openapi.json"
  ```

  then regenerate the client (`swift build` runs the generator plugin) and run
  `swift test`.

- **What `swift test` asserts** (`OpenAPISpecContractTests`): the snapshot
  exists, is an OpenAPI 3.x document, and still describes both endpoints
  `PaletteAPIClient` consumes — `GET /api/v1/printer_profiles` and
  `GET /api/v1/colors` with the required `printer_profile_id` query parameter.

- **`/api/v1` shape findings at adoption (2026-11):** none — the published
  spec's `PrinterProfilesResponse` and `ColorsResponse` match the existing
  hand-written DTOs field-for-field (`printer_profiles[]`;
  `printer_profile` + `colors[]` with `id`, `name`, `hex`, `rgb`, `palette_id`,
  `palette_name`, `sort_order`, `responses`). The generated-client migration
  is therefore shape-neutral for this app.
