# Generated OpenAPI client for `PaletteAPIClient`

Issue #39 migrates `PaletteAPIClient` from a hand-rolled `URLSession`
client to a typed client generated by
[`swift-openapi-generator`](https://github.com/apple/swift-openapi-generator)
from the OpenAPI document published by `color_matching`
([#110](https://github.com/viamin/color_matching/pull/110)).

This document records the expected layout, the behavior that must survive
the migration, and the notes the final PR description must capture.

## Expected layout

```
ColorComposerCore/Package.swift                     # adds swift-openapi-generator (plugin) + swift-openapi-runtime
ColorComposerCore/Sources/ColorComposerCore/OpenAPI/openapi.yaml   # committed spec (from color_matching #110)
```

`Package.swift` gains:

- a package dependency on `apple/swift-openapi-generator` and
  `apple/swift-openapi-runtime`,
- the `OpenAPIGenerator` build plugin on the `ColorComposerCore` target,
- a product dependency on `OpenAPIRuntime`.

`PaletteAPIClient` is expected to **wrap** the generated `Client` (or be
replaced by a thin adapter) rather than leak generated types into the app:
the disk-cache/offline-stale behavior in `ProfileColorCache` and
`ColorCatalog` stores `PaletteColorDTO` wire snapshots and must keep
working unchanged.

## Wire contract that must not change

`ColorComposerCore/Tests/ColorComposerCoreTests/PaletteAPIClientContractTests.swift`
pins the externally observable behavior; every test there must stay green
across the migration:

| Behavior | Pinned by |
| --- | --- |
| `GET /api/v1/printer_profiles`, `Accept: application/json` | `testFetchPrinterProfilesRequestsTheVersionedPath` |
| `GET /api/v1/colors?printer_profile_id=N` | `testFetchColorsSendsThePrinterProfileIDQuery` |
| snake_case envelopes (`printer_profiles`, `printer_profile`, `colors`, `responses`) | same two tests + `PaletteAPIClientContractTests` bodies |
| response-less colors stay response-less (missing ≠ measured zero) | `testFetchColorsKeepsResponselessColorsResponseless` |
| bearer token trimmed; absent/blank token sends no `Authorization` header | `testSendsBearerTokenWithWhitespaceTrimmed`, `testOmitsAuthorizationHeader…`, `testBlankTokenIsTreatedAsAbsent` |
| HTTP 401 → `PaletteAPIError.unauthorized` (re-auth flow hook) | `testUnauthorizedStatusMapsToUnauthorizedError` |
| other non-2xx → `.badStatus(code)` | `testServerErrorStatusMapsToBadStatus` |
| undecodable 2xx body → `.malformedResponse` | `testUndecodableSuccessBodyMapsToMalformedResponse` |
| `testConnection` accepts any 2xx, reports 401 | `testTestConnection…` |

`ColorComposerCore/Tests/ColorComposerCoreTests/OpenAPIClientMigrationTests.swift`
additionally asserts the structural preconditions and fails until the
migration lands: the manifest declares generator + runtime, and the
committed spec declares the two `/api/v1` operations with the
`printer_profile_id` query parameter and the snake_case envelope keys.

Caching/offline behavior that must remain intact is pinned by the
existing suites: `ProfileColorCacheTests` (per-server/profile disk cache,
namespace normalization, clear semantics, snake_case on-disk format) and
`PaletteAPIClientTests` (401 handling). The offline fallback only serves
cached data for transport failures — that policy lives in
`ColorCatalog` and is unchanged by this migration.

## PR description checklist (fill in during implementation)

- [ ] Generated-client migration notes: plugin/target layout, generated
      type names, how `PaletteAPIClient` wraps (or is replaced by) the
      adapter.
- [ ] Any `/api/v1` shape changes found while generating (fields the
      hand-rolled DTOs ignored, new optional fields, envelope differences
      between spec #110 and current responses).
- [ ] Solver parity results: corpus version/generator string, number of
      cases, ties, exclusions, and weight-handling outcomes —
      `swift test --filter SolverParityCorpusTests` output summary.
- [ ] Confirmation that disk cache + offline fallback behavior is
      unchanged (suites above green; no cache-format migration needed).
